# cdn-deploy

Обвязка CDN-фронтинга для ноды Remnawave. `deploy.sh` одной командой ставит nginx перед xhttp-инбаундом xray, выпускает и продлевает сертификаты Let's Encrypt и тюнит ядро против 503 под нагрузкой. `check.sh` проверяет все серверы подписки: сначала L7-пробой, затем настоящим трафиком через локальный xray.

```
Клиент --VLESS+xHTTP (TLS, 443)--> CDN edge --HTTPS--> origin nginx :8444 --HTTP--> xray 127.0.0.1:4443
Клиент --VLESS Reality (TCP, 443)--------------------------------------------------> xray :443
Клиент --Hysteria2 (UDP, 443)------------------------------------------------------> xray :443
```

Скрипт отвечает за origin-сторону: nginx, сертификаты origin, их продление, сетевой тюнинг. Конфиг xray на ноде он не пишет: им управляет панель, а xhttp-инбаунд вы вставляете в панель сами (шаг ниже). Edge-сертификат CDN выпускает и продлевает Timeweb.

## Что нужно заранее

- **Сервер:** Ubuntu 22.04/24.04 или Debian 12, доступ root. Нода Remnawave работает в docker-контейнере `remnawave-node`. Если контейнер называется иначе, поправьте `NODE_RELOAD_CMD`.
- **Три домена:**
  - `VLESS_DOMAIN` и `HY2_DOMAIN`: A-записи на IP ноды;
  - `CDN_DOMAIN`: CNAME на CDN-ресурс.
- **Сертификаты**, один из режимов:
  - `dns-cloudflare` (по умолчанию): зона доменов в Cloudflare и API-токен с правом `Zone:DNS:Edit` на эту зону;
  - `http-01`: порт 80 ноды открыт из интернета. Сертификат для `CDN_DOMAIN` в этом режиме не выпускается (домен смотрит на CDN), и origin использует сертификат `VLESS_DOMAIN`.
- **CDN-ресурс Timeweb:**
  - источник: IP ноды и порт `NGINX_TLS_PORT` (8444), опция HTTPS для источника включена;
  - домен раздачи: `CDN_DOMAIN`. Timeweb принимает только поддомен (`cdn.example.com`) с CNAME на технический домен ресурса (`*.cdn.twcstorage.ru`), сертификат выпускается в панели Timeweb (Let's Encrypt);
  - кэширование оставьте включённым: origin отдаёт на туннель `Cache-Control: no-store`, и Timeweb по документации его соблюдает. По отчётам из чатов, с выключенным кэшем ресурс отвечает 403. «Игнорировать заголовки кэширования», «Всегда онлайн» и «Ускорение загрузки больших файлов» не включайте.
- **Firewall:**
  - 8444/tcp открыт для CDN;
  - 443/tcp и 443/udp открыты для Reality и Hysteria2;
  - 80/tcp открыт в режиме `http-01`.
- **fail2ban:** HTTP-джейлы банят адреса edge CDN. Оставьте только `sshd`.

## Установка

```bash
git clone <url-репозитория> cdn-deploy && cd cdn-deploy
sudo ./deploy.sh --dry-run    # настройки и план шагов, ничего не меняет
sudo ./deploy.sh
```

Скрипт спрашивает параметры: Enter оставляет значение в скобках. Ответы сохраняются в `.env` с правами 600, потому что там токен Cloudflare. Затем выполняются шаги:

| # | Шаг | Что делает |
|---|---|---|
| 1 | preflight | root, bash 4+, поддерживаемая ОС |
| 2 | input | опрос параметров, запись `.env` |
| 3 | config | загрузка `.env`, проверка обязательных значений |
| 4 | packages | доустановка nginx, certbot, python3-certbot-dns-cloudflare, curl, jq, openssl, coreutils, gettext-base, procps |
| 5 | certs | выпуск сертификатов; сертификат, валидный ещё 30+ дней, не трогается |
| 6 | renew-hook | хук продления и `certbot.timer` |
| 7 | sysctl | тюнинг ядра, лимиты nofile, резерв портов `XHTTP_PORT` и `NGINX_TLS_PORT` |
| 8 | nginx | конфиг из `templates/`, `nginx -t`, reload; при ошибке возвращает прежний конфиг |
| 9 | remnawave | готовые конфиги для панели в `out/remnawave/` и инструкция |
| 10 | validate | послойная проверка, см. ниже |

Повторный запуск безопасен:
- значения из `.env` становятся дефолтами;
- неизменённые файлы не перезаписываются;
- валидные сертификаты не перевыпускаются.

Ручные правки в `/etc/nginx` затираются следующим запуском, поэтому меняйте шаблоны в `templates/`.

Запуск без вопросов: заполните `.env` по образцу `.env.example` и запустите `sudo ./deploy.sh </dev/null`. Недостающее обязательное значение даёт exit 2.

## Параметры

Полное описание с комментариями лежит в `.env.example`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `VLESS_DOMAIN` | — | домен прямого VLESS; его сертификат служит origin, если нет своего для CDN |
| `HY2_DOMAIN` | — | домен Hysteria2 с настоящим сертификатом |
| `CDN_DOMAIN` | — | домен CDN-ресурса: `server_name` origin, host xhttp |
| `ORIGIN_IP` | автоопределение | публичный IPv4 ноды, origin CDN-ресурса |
| `XHTTP_PORT` | `4443` | локальный порт xhttp-инбаунда xray |
| `XHTTP_PATH` | `/api/v2.jpg/` | путь xhttp: короткий, с точкой в сегменте, одинаковый на инбаунде и хосте |
| `NGINX_TLS_PORT` | `8444` | порт origin nginx для CDN |
| `UUID` | генерируется | id клиента VLESS |
| `CERT_MODE` | `dns-cloudflare` | `dns-cloudflare` или `http-01` |
| `CF_API_TOKEN` | — | токен Cloudflare, нужен в режиме `dns-cloudflare` |
| `LE_EMAIL` | пусто | контакт Let's Encrypt |
| `NODE_RELOAD_CMD` | `docker restart remnawave-node` | перезапуск ноды после продления сертификата Hysteria2 |
| `ISSUE_CDN_ORIGIN_CERT` | `true` | выпускать ли origin-сертификат для `CDN_DOMAIN` |

## Шаг в панели Remnawave

На свежей ноде первый запуск остановится на слое 1 проверки (exit 8): xray ещё не слушает `XHTTP_PORT`, потому что инбаунда в панели нет. Так и должно быть. Дальше:

1. Добавьте объект из `out/remnawave/inbound-xhttp-cdn.json` в массив `inbounds` конфиг-профиля ноды.
2. В хосте для `CDN_DOMAIN` вставьте `out/remnawave/host-xhttp-extra.json` в поле `extra`. Остальные настройки хоста:
   - адрес `CDN_DOMAIN`, порт 443;
   - транспорт xhttp, режим packet-up, путь `XHTTP_PATH`;
   - host и SNI `CDN_DOMAIN`, TLS.
3. Когда нода примет конфиг, запустите `sudo ./deploy.sh` ещё раз.

Поля обфускации должны совпадать на инбаунде и хосте один в один, `deploy.sh` сверяет их перед записью файлов. Подробности и тюнинг против 503 описаны в [remnawave/README.md](remnawave/README.md).

## Проверка после установки

Шаг validate проверяет цепочку снизу вверх. На первом сломанном слое он останавливается с exit 8 и пишет, что исправить.

| Слой | Что проверяется | Частые причины провала |
|---|---|---|
| 1. xray | `127.0.0.1:XHTTP_PORT` принимает соединения | инбаунд не добавлен в панель, или нода ещё не приняла конфиг |
| 2. origin nginx | `/cdn-check` на `NGINX_TLS_PORT` отвечает 204 с `X-CDN-Origin` | nginx не запущен или отдаёт не сайт cdn-deploy |
| 3. xhttp path | `XHTTP_PATH` + `test` и `XHTTP_PATH` без завершающего слеша отвечают 400 с падинг-заголовком инбаунда | 404: путь или host расходятся с панелью; 502/504: nginx не достаёт до xray; 301 на путь без слеша: конфиг nginx устарел |
| 4. CDN edge | `https://CDN_DOMAIN/cdn-check` отвечает 204 от этого origin | см. ниже |

Причины провала на слое 4:
- нет CNAME на ресурс;
- edge-сертификат не покрывает `CDN_DOMAIN`: привяжите сертификат к ресурсу, применение занимает до 30 минут;
- 502/504: origin ресурса не `ORIGIN_IP:NGINX_TLS_PORT` по HTTPS, или порт закрыт;
- 403: ресурс неактивен или не пропускает GET;
- 451: домен заблокирован, нужен новый.

Кроме того, validate предупреждает, если `ORIGIN_IP` не адрес этой машины и если xray слушает `XHTTP_PORT` не только на loopback.

## Чекер подписки

```bash
./check.sh 'https://panel.example.com/api/sub/<shortUuid>'
./check.sh --fast 'https://panel.example.com/api/sub/<shortUuid>'   # только L7, без туннелей
```

Нужны bash 4+, curl, jq, openssl и coreutils. Для туннелей нужен ещё xray: на ноде он живёт внутри контейнера, поэтому поставьте отдельный бинарь. Версия должна быть по ту же сторону от 26.6, что и у ноды (см. «Версия xray» ниже), иначе чекер покажет FAIL на рабочих серверах:

```bash
v=26.3.27   # версия xray на ноде
case "$(dpkg --print-architecture)" in amd64) a=64 ;; arm64) a=arm64-v8a ;; esac
curl -fsSLo /tmp/xray.zip "https://github.com/XTLS/Xray-core/releases/download/v$v/Xray-linux-$a.zip"
sudo apt-get install -y unzip && sudo unzip -o /tmp/xray.zip xray -d /usr/local/bin
```

Без xray чекер выполняет только L7-проверки, а туннели помечает SKIP. Чекер ничего не меняет в системе, root ему не нужен. Запускайте его с любой Linux-машины:
- с ноды он проверит связность из дата-центра;
- с машины в сети клиента он покажет то, что видят пользователи.

Как проверяется сервер:

| Сервер | L7-проверка | Туннель |
|---|---|---|
| xhttp через TLS (CDN) | `XHTTP_PATH` + `test` отвечает 400 с падинг-заголовком из `extra` ссылки; коды CDN (403, 451, 502/504, 503) расшифровываются | локальный xray с этим сервером как outbound, запрос `CHECK_PROBE_URL` через socks, ждём 204 |
| Reality, TLS | TLS-рукопожатие с SNI ссылки | то же |
| Hysteria2 | ответ QUIC version negotiation по UDP; с salamander пропускается | то же, salamander поддерживается |
| Shadowsocks и серверы без TLS | TCP-соединение | то же |
| протоколы, которых чекер не знает | SKIP | SKIP |

Итог строки берётся из туннеля, если он был: L7-ответ показывает, что сервер жив, но не что он несёт трафик. Задержка в таблице тоже от туннеля, если он был.

Коды выхода:
- 0: ни одного FAIL;
- 1: есть FAIL, или подписку не удалось получить;
- 2: неверные аргументы;
- 3: не хватает команды.

Ссылки с `allowInsecure=1`: в xray эту опцию убрали, поэтому чекер закрепляет сертификат, который показывает сервер (`pinnedPeerCertSha256`). Для Hysteria2 так нельзя, сертификат по TCP не получить, поэтому в ссылке нужен `pinSHA256`.

Переменные окружения:
- `CHECK_PROBE_URL`: что запрашивать через туннель, должен отвечать 204. По умолчанию `http://www.gstatic.com/generate_204`.
- `CHECK_XRAY`: путь к xray.
- `CHECK_USER_AGENT`: Remnawave выбирает формат подписки по User-Agent. По умолчанию `v2rayNG/1.10.5`, это base64-ссылки. Чекер также понимает JSON sing-box и xray-json.

## Коды выхода deploy.sh

| Код | Значение |
|---|---|
| 0 | всё готово, все слои проверки прошли |
| 1 | шаг не выполнился, сообщение называет причину; при непредвиденной ошибке — команду и строку |
| 2 | неверный или недостающий параметр |
| 3 | нет нужной команды, или пакет не установился |
| 4 | нужен root |
| 5 | ОС не поддерживается |
| 6 | не удалось выпустить сертификат |
| 7 | nginx не принял конфиг; прежний конфиг восстановлен |
| 8 | проверка: не прошёл слой, указанный в сообщении |

## Эксплуатация

- **Прямое подключение к origin, мимо CDN:** origin работает без HTTP/2, и xhttp-клиенту нужен ALPN `http/1.1`. Через CDN этого не требуется, edge сам ходит к origin по HTTP/1.1.
- **Продление сертификатов** выполняет `certbot.timer`. Хук продления:
  - перезагружает nginx;
  - перезапускает ноду (`NODE_RELOAD_CMD`), только если продлился сертификат `HY2_DOMAIN`, так как xray читает его при старте.

  В режиме `http-01` хук на время продления поднимает на порту 80 временный сайт.
- **Особенности Timeweb CDN:**
  - по документации пропускает только GET, HEAD и OPTIONS, поэтому uplink идёт в режиме packet-up через GET;
  - по отчётам из чатов на длинные URL и заголовки отвечает 403;
  - по тем же отчётам ресурс засыпает после 7 дней без запросов.
- **Версия xray:** в xray 26.6 поля сессии xhttp переименованы (`sessionPlacement` стал `sessionIDPlacement`, добавились `sessionIDTable` и `sessionIDLength`). Файлы в `remnawave/` используют новые имена, а xray до 26.6 их молча игнорирует. Поэтому нода и клиентские приложения должны быть по одну сторону: обе на xray 26.6+ или обе ниже. При смешении каждый запрос получает 400.
  - На 26.6+ id сессии уходит в query, и URL получается ровно `XHTTP_PATH`. Timeweb срезает с него завершающий слеш. Origin принимает обе формы, а слой 3 проверки это проверяет.
  - По отчётам, remnawave-node 2.8.1 (xray 26.6.27) «ломал CDN», а откат на 2.7.0 (xray 26.3.27) помогал. Наши тесты воспроизводят именно эту картину: origin без обработки пути без слеша отвечает на него 301.
  - С xray 26.6+ нода по умолчанию не доверяет `X-Forwarded-For`, и все клиенты CDN видны ей как 127.0.0.1.
- **`.env`** содержит токен Cloudflare: права 600, в git не попадает (`.gitignore`).

## Разработка

Правила, контракты модулей и дорожная карта описаны в [tech.md](tech.md). Линт и тесты:

```bash
shellcheck deploy.sh check.sh lib/*.sh tests/*.bats
bats tests/
```

Тесты не трогают систему. `CDN_DEPLOY_SYSROOT` уводит системные файлы во временный каталог, а внешние команды (certbot, nginx, curl, xray и другие) заменены заглушками. Целевые ОС: Ubuntu 22.04/24.04 и Debian 12. Тесты гоняются в их Docker-образах, под root и под обычным пользователем.
